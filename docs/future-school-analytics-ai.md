# Future School — общая аналитика и ИИ-анализ обратной связи

## Навигация единой платформы
- Главная панель
- Обратная связь: отправка, история, охват, аналитика
- Карта наблюдений: создание и аналитика
- НИШ: задания, расписание, результаты и аналитика
- Future School AI (общий помощник)
- Администрирование: сотрудники, нагрузка, роли и разрешения

## Аналитика обратной связи
### Охват
- Учебный год и период (неделя, месяц).
- Плановый список классов, учеников и назначенных преподавателей.
- Вовремя опубликовано / ожидается / не опубликовано (с детализацией по предмету, классу, преподавателю).
- Расчёт статуса только относительно ожидаемых публикаций; пустые назначения не считать просрочками.
- Переход из проблемной строки к разрешённой странице обратной связи.

### ИИ-анализ по кнопке
Интерфейс: «Провести ИИ-анализ» с выбором периода и разрешённой области данных.
Не запускать автоматически при открытии аналитики.

Серверный процесс:
1. Проверить Supabase Auth и явное право `feedback.ai_analyze` с областью кампуса/класса/школы.
2. Получить только опубликованные или отдельно разрешённые записи для выбранного периода, внутри серверной функции с соблюдением RLS/авторизации.
3. Выявить повторяющиеся темы обратной связи об одном ученике на основании нескольких независимых сообщений. Не приписывать диагнозы или мотивы; отделять объективную частоту от интерпретации текста.
4. Выдать ответственному сотруднику сигналы для ручной проверки: ученик, тема, динамика, количество наблюдений, цитируемые выдержки с ограничением длины, ссылки на исходные записи.
5. Не предоставлять другим родителям данные чужих детей; не давать доступ к общешкольному ИИ-анализу по умолчанию обычному преподавателю.
6. Отмечать «недостаточно данных», если сообщений мало, а не характеризовать ученика по одной жалобе.
7. Журналировать запуски ИИ-анализа и не публиковать персональные сведения внешним аналитическим сервисам без одобренных договорных и технических гарантий.

Данные результата: `analysis_run_id`, `period`, `scope`, `generated_at`, `signals[]`, `source_feedback_ids[]`, `review_status`. Модель возвращает объяснимые признаки, окончательное решение принимает сотрудник.

## Роли
- Суперадмин: полный управленческий доступ.
- Директор: анализ школы, в том числе ИИ по запросу, без права назначать НИШ по умолчанию.
- Завуч: аналитика по соответствующей области и отдельно выданные разрешения.
- Учитель: свои назначения, своя обратная связь; расширенный анализ по явному разрешению.
- Родитель: только опубликованные материалы собственных детей, без сводного анализа школы.

## Этапы реализации

- Добавить общий маршрутизатор и навигацию внутри нового портала.
- Отдельно интегрировать метрики охвата и серверно ограниченные выборки.
- Реализовать безопасную кнопку «Провести ИИ-анализ» после серверного контроля доступа и ручной проверки результатов.
